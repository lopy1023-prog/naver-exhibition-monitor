# 과거 공식 공고 기반 수원 판별 보강

## 범위와 근거

사용자 요청은 과거 사례의 반복 구조를 확인해 기존 LH 알림을 보강하는 것이다. 모델을 재학습시키는 대신 공식 사례, 판별 규칙, 회귀검증 자료를 저장한다. 첨부파일 본문은 열지 않는다. GH·수원시 별도 출처 추가는 이번 LH 내부 보강과 분리한다.

- 기간: 2022-01-01~2026-10-16, 공식 목록 9개 검색, 고유 338건, 15개 유형.
- 제목의 수원 직접 표기 212건, 경기남부 등 광역 후보 126건. 모두 수원 확정 공고라는 뜻은 아니다.
- 상세: 유형별 최신/최초와 연도별 광역 사례를 고른 44건. 역사 전체의 완전한 목록이나 통계적 정확도 표본으로 주장하지 않는다.
- 실제 상세 공급표에서 `매입다가구(경기수원시)` 및 `(경기수원시) 서수원엠코타운르본느`를 확인했다. 기존 광역 후보에는 포함되지만 단순 본문 일부 추출로는 수원 직접 표기를 놓쳤다.
- 별도 자료실 사례 `bbsSn=9102431609`는 제목이 용인시 안내지만, 공개 첨부파일 목록에 `[수원광교41단지]서류제출대상자명단(현장접수).pdf`가 있다. 기존 파일명 판별로 수원 대상에 포함됨을 실제 페이지에서 확인했다. 파일 본문은 열지 않았다.

## 변경과 검증

1. 임대·분양·토지·상가 검색의 날짜 필드를 실제 공식 양식 `startDt/endDt`, ISO 날짜, `schTy=0`, `srchY=N`으로 수정한다. 응답이 요청 날짜를 되돌려 주는지 매 페이지 확인하고, 반환 게시일이 기간 밖이면 실패한다. 유효한 0건 응답도 날짜가 맞아야 정상이다.
2. 공식 `공급정보` 표의 지역/주소/단지명에 해당하는 열만 추가 근거로 사용한다. 열 병합을 반영하고 구조가 맞지 않으면 확정하지 않는다. 문의처·접수처·소득·면적은 지역 근거로 쓰지 않는다. 광역 후보는 계속 알림 대상이다.
3. 과거 목록 사례 338건을 재현 검증용으로 저장한다. 공급표 사례와 비슷한 단지명(성남고등 등), 문의처 주소를 음성 대조군으로 검증한다.
4. 판별 기준 버전만 바뀐 기존 공고를 신규 변경 알림으로 재발송하지 않는다. 같은 실행에서 실제 일정/상태/본문이 바뀌면 해당 변경은 유지한다.
5. 날짜 문제의 실패 재현 → 수정 후 통과, 전체 Python/Node 검사, 수정한 실제 수집기로 공식 과거 목록 재조회, 운영 기준기간의 공식 목록 대조 후 반영한다. 기존 알림 이력과 예약을 유지한다.

## 한계

첨부파일 안에만 수원 정보가 있으면 수원 확정은 못할 수 있다. 경기남부·경기도·수도권·전국 후보를 유형과 개인 자격으로 제외하지 않아 사용자가 공고문을 직접 확인할 수 있게 한다. 외부 기관, 향후 사이트 구조 변경, 실행/휴대폰 알림 지연까지 무누락으로 보장하지 않는다.

## 반영 전 검증 결과

- 날짜 필드 무시와 요청기간 밖 게시일: 수정 전 3개 검사 실패, 수정 후 통과.
- 공급표 실제 구조 2종 및 규칙 버전 이관: 수정 전 3개 검사 실패, 수정 후 통과. 본문 rowspan의 연락처 오인 재현 검사도 실패를 확인하고 방어 후 통과.
- 실제 수정 수집기로 과거 검색 9개와 운영 기준기간 검색 4개 재조회: 13/13 완료, 날짜 응답 확인, 기존 표본/운영 목록 대비 빠진 ID 0개.
- 상세 44개 재판별: 기존 알림 대상 전부 유지, 공급표 근거로 수원 직접 확인이 2개 추가됨. 규칙 버전 이관만으로 발생하는 변경 이벤트 0개.
- 과거 목록 338개는 직접 확인 212개/광역 후보 126개 모두 포함. 이것은 선택 표본 결과이며 전체 과거 공고 완전성이나 미래 정확도 보장이 아니다.
- 별도 검수 에이전트는 사용량 제한으로 실행 실패했다. 독립 검수 완료로 보고하지 않으며, 직접 변경점 검토와 위 재현·실데이터 검증을 수행했다.
- 첫 운영 실행의 최종 대조에서 `2015122300020900`(경기북부 김포·포천 전용)이 상세 요약의 일반적인 `모집지역 : 경기도` 때문에 광역 후보가 되는 기존 우선순위 오류를 발견했다. 실제 페이지로 재현 후 지역 우선순위를 수정했다. 수원 공급표 근거가 있는 경우는 계속 포함한다. 이번 실행에서 잘못 추가된 알림 ID 한 개만 정리하며 원래 62개 알림 이력은 그대로 보존한다. 이 사례를 포함한 Python 52개/Node 19개 검사를 통과했다.
