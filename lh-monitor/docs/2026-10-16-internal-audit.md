# LH 내부 장애·경계조건 시험

범위는 기존 LH 20개 수집 경로와 기존 예약이다. 외부 기관을 추가하지 않고 첨부파일 본문을 열지 않는다. 시뮬레이션은 운영 JSON과 휴대폰 알림을 쓰지 않는 별도 출력으로 실행한다.

## 재현한 문제와 수정 범위

1. 같은 날 10시/14시 접수가 있을 때 10시의 상태 전환이 14시 토큰까지 미리 소비했다. 상태와 연결할 일정은 현재 시각 이하에서 고르고, 미래 일정만 있으면 별도 상태 근거로 알리되 미래 토큰을 소비하지 않는다.
2. 접수마감·취소 상태 또는 공식 접수 종료시간이 지난 일정에서도 시작 이벤트가 나왔다. 종료된 일정의 날짜 경로를 막고, 실제 `접수중` 전환에 의한 재개 근거는 유지한다.
3. `공급지역: 부산 ... 문의처: 수원 ...`처럼 정보가 가까우면 지역 추출이 문의처까지 읽었다. 문의처·연락처 등의 경계에서 지역 근거를 끊고 판별 버전을 올려 규칙 수정만으로 과거 공고를 재알림하지 않는다.
4. 공급표의 빈/잘못된 colspan·rowspan 값이 상세 전체 확인을 실패시켰다. 빈 값은 기본 1로 해석하고 해석 불가능한 표/행은 지역 확정 근거로 쓰지 않는다. 광역 후보와 공고 자체는 유지한다.

## 검증

- 먼저 실패하는 회귀검사를 작성하고 각 문제를 재현한다.
- 다중 접수 순위·지연된 상태·실패 후 시간 간격·미래 일정·종료 일정·재개를 연속 실행으로 검증한다.
- 실제 운영 상태의 순서/첨부/일정 정렬 변화 재생과 보강 출처 실패를 시험한다. 기존 이력 보존, 중복 0건, 실패를 신규 없음으로 처리하지 않는지 확인한다.
- 기존 과거 공식 목록 338건 및 전체 Python/Node 검사도 통과해야 한다.
- 수정 반영 후 실제 전체 수집을 검증한다. 모의 공고를 운영에 넣거나 새 휴대폰 시험 알림을 발송하지 않는다.

## 교차 검수와 이관

별도 검수에서 만료 후 늦은 상태의 빈 토큰 중복, 반복 공급지역 누락, 실제 HTML에서 상태 문구가 본문 변경으로 중복 처리되는 경우를 추가로 재현했다. 상태 연결은 만료 여부와 별개로 이미 지난 일정의 토큰을 사용하고, 지역 항목을 먼저 나눠 각각 검사한다.

의미 본문 hashVersion=3은 공고상태 메타데이터를 제외한다. 첫 2→3 이관에서는 현재 HTML에 이전 상태만 복원한 v2 비교용 해시를 계산한다. 이 값이 이전 저장 해시와 같을 때만 정책 변경으로 맞추고, 다르면 실제 본문 변경을 계속 알린다. 비교용 임시 값은 운영 JSON에 저장하지 않는다. 분류 geographyVersion=3의 기준 보강만으로 기존 공고를 재발송하지 않는다.

운영 사본 4,822건을 12회 섞어 재생한 중복 이벤트는 0건이다. 20개 경로×6개 지역 유형의 신규 120건, 명백한 타 지역 60건, 반복 이벤트 120건을 추가 시험했다. 36개 시간 조합도 검증했다. 접수 토큰 168개에 미래 일정이 조기 소비된 흔적은 없어 기존 토큰을 초기화하지 않았다. 운영 이력 62건, 기존 예약, 실행 주기는 유지한다.

전체 Python 64개/Node 19개 검사 통과. 실패 조건을 먼저 재현한 뒤 수정했다. 별도 검수에서도 64개 통과와 v2 실제 파서의 HTML 표현 3종 이관 호환성을 확인했고, 핵심 미해결 결함은 찾지 못했다. 운영 캐시의 실제 공고 7개는 이전 정책과 비교 값이 일치해 기준 변경만의 이벤트가 0개였다. 이 결과가 미래 사이트 변경까지 무결함을 보장하는 것은 아니다.
