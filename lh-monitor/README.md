# LH 수원 공고 모니터

공식 LH청약플러스 → GitHub Actions → data/lh/lh-report.json → 기존 ChatGPT 예약 알림 흐름을 유지한다. 네이버/알바몬 모니터는 변경하지 않는다.

## 감시 범위

- 모집공고: 임대·분양·토지·상가·사전청약. 기존 기준 시작일을 보존한다.
- 청약캘린더: 이번/다음 달 모든 날짜와 전체보기 JSON의 숨김 항목까지 건수 대조.
- 공지사항·입주안내: 해당 연도 전체 목록/상세. 자료실: 전체 목록/상세.
- 공급계획: 임대·분양·토지·상가 전체 페이지. 입주계획 전체 페이지.
- 선착순 계약: 토지·분양·분양전환임대·상가·임대상가·임대주택의 공개 전체 행.

수원 직접 관련과 경기남부·경기도·수도권·전국 후보를 유형에 관계없이 포함한다. 화성·오산 직접 관련은 추가 범위로 유지한다. 나이·소득·자산·방 개수·면적으로 미리 제외하지 않는다. 담당기관 연락처 주소만으로 수원 공급을 확정하지 않는다. 공식적으로 확인되지 않은 지역·방 개수·자격은 확인 필요로 남긴다.

첨부파일은 이름과 공식 링크만 저장한다. 본문은 내려받거나 분석하지 않는다. 첨부에만 지역/일정 정보가 있으면 확정하지 못할 수 있으며 광역 후보를 제외하지 않는다.

## 이벤트와 중복 방지

기존 alertHistory와 alertId는 보존한다. 새 출처의 첫 정상 수집은 기준선만 만들고 과거 자료를 대량 발송하지 않는다. 공고문과 캘린더는 panId로 합친다. 창 밖 과거 일정과 이미 확인한 공고 식별자를 보존한다. 조회수·수집 시각·목록/일정/첨부 순서 변경은 알림 사유가 아니다.

신규·정정·추가·잔여 모집과 의미 있는 본문/첨부목록/일정/상태 변경을 이벤트로 기록한다. 선착순 행의 이탈/재등장도 변경으로 기록하되 소진·계약완료로 단정하지 않는다. 계획 자료는 informationOnly=true로 신청 모집과 구분한다.

receptionStarted는 접수중 전환 또는 공식 시작일·시각 도래를 확인한다. 같은 날짜에 정확한 시각이 있으면 날짜만 있는 정보보다 우선한다. 시작 일정과 늦게 반영된 상태 변경은 한 번만 알린다. 마감 후 접수중 전환은 재개 이벤트다. 발표·서류제출·계약 일정을 접수 시작으로 처리하지 않는다. 개인별 순위/자격과 해당 접수시간은 개별 공고를 확인해야 한다.

## 실패와 실행 주기

원래 cron 7,17,27,37,47,57 * * * *와 55분 freshness 기준을 유지한다. GitHub 지연에 따라 실제 실행 시각은 달라질 수 있다. 정시·즉시 알림은 보장하지 않는다.

페이지/건수/식별자 또는 현재 상세 확인이 실패하면 프로세스를 실패 종료한다. 정상 상태 두 파일과 알림 이력을 보존하고 오류 보고에도 마지막 정상 이력을 남긴다. 실패를 신규 없음으로 처리하지 않는다. 기존 예약은 수집시각 지연만으로 경고하거나 매번 상태를 보고하지 않는다.

## 실행과 검증

    python -m pip install -r lh-monitor/requirements.txt
    python -m unittest discover -s lh-monitor/tests -v
    node --test
    python lh-monitor/monitor.py
    python lh-monitor/monitor.py --validate

운영 상태 사본을 별도 폴더에 둔 뒤 --data-dir로 실데이터를 검증한다. 시뮬레이션은 운영 파일을 쓰지 않는다.

    python lh-monitor/monitor.py --data-dir /tmp/lh-validation
    python lh-monitor/simulate.py --baseline /tmp/lh-baseline/lh-state.json --current /tmp/lh-validation/lh-state.json --output /tmp/lh-simulation.json

개인 소득·자산·생년월일·인증정보는 공개 저장소에 저장하지 않는다. 청약 신청은 사용자가 공식 사이트에서 자격·순위·서류·접수시간을 확인한 뒤 진행한다.
